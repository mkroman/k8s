The Zigbee2MQTT container runs privileged because a hostPath device is not
added to the container's device cgroup; without that, opening
{{ .Values.coordinator.devicePath }} fails with EPERM. The process still runs
as UID 1000 and needs coordinator.groupId (default: 20) to match the device's
group. The init container, emulator sidecar and probe remain unprivileged.
See the chart README before changing coordinator.privileged.
{{- else }}
coordinator.devicePath is empty: the device hostPath, /run/udev mount and USB
nodeSelector are disabled, and the Zigbee2MQTT container stays unprivileged.
It reaches the coordinator at:

  {{ .Values.config.serial.port }}

The default is the ser2net Service in the `ser2net` namespace. Its
NetworkPolicy must allow egress to networkPolicy.ser2netNamespace and
networkPolicy.ser2netPort. For the emulator or a remote adapter, point
config.serial.port at that endpoint and leave ser2netNamespace empty.
{{- end }}

Before the first start, create the Secret referenced by `secret.name`
(default: zigbee2mqtt-secrets) with a key named `secret.key`
(default: secret.yaml) containing:

  password: <mqtt password>

It is mounted at /app/data/secret.yaml and referenced from configuration.yaml
as "!secret.yaml password". See the chart README for a kubeseal example.

The data volume holds database.db and coordinator_backup.json. To keep the
existing Zigbee network, restore that directory (or provide the network key in
secret.yaml); otherwise Zigbee2MQTT generates a new network key and all devices
must be paired again.

Frontend (cluster-internal):
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "zigbee2mqtt.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}
